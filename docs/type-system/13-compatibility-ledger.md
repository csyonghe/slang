# Compatibility and completeness ledger

This ledger is the bridge between the current compiler and the normative replacement design. It
prevents source behavior, generated documentation, or a redesign preference from silently becoming
a language rule.

The investigation baseline is official `master` at
`aaa07fe296560ffefeaf2e39d0aed5658b641a21` (2026-07-17).

## Dispositions

```text
CompatibilityDisposition =
    Preserve | PreserveByMode | Replace | IntentionalChange | Open | Unclassified
```

`Unclassified` is permitted only while collecting evidence for this ledger. No normative rule,
published compatibility profile, or implementation gate may retain it.

| Disposition           | Meaning                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------- |
| **Preserve**          | Current observable behavior is accepted as normative compatibility behavior.              |
| **PreserveByMode**    | Retained only under a named Slang language version.                                       |
| **Replace**           | Current implementation representation changes while user-visible behavior is preserved.   |
| **IntentionalChange** | The new language rule deliberately changes observable behavior and needs migration notes. |
| **Open**              | Evidence or design review is incomplete; implementation must not choose implicitly.       |
| **Unclassified**      | Evidence collection has not yet assigned a reviewable disposition.                        |

## Syntax and parsing decisions

| Topic                                  | Verified current behavior                                                                                                 | Proposed disposition                                                                          | Resolution or remaining work                                                                                                                                                                                                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| identifiers as keywords                | lexer emits identifiers; parser scope lookup resolves `SyntaxDecl`                                                        | **IntentionalChange** to a Slang-2026 reserved/contextual vocabulary                          | **Closed**: every declaration-kind and statement introducer plus `var` and `let` is reserved; compiler-owned `__...` introducers are reserved as a class. Other grammar words remain contextual only where the grammar says so.                                                                   |
| user `syntax` declarations             | scoped/order-dependent aliases can change fine parsing                                                                    | **IntentionalChange**: excluded from the user language                                        | **Closed**: compiler-owned syntax registration is standard-environment/bootstrap input. User source cannot declare `syntax` or `attribute_syntax`, create scope bindings for them, or change later parsing.                                                                                       |
| `>>` in generics                       | parser mutates lookahead to split the token contextually                                                                  | **Preserve**, **Replace** with virtual token slices                                           | Closed by `LEX-TOK-001` and the generic-closing rule: slices partition logical spelling and surrounding trivia remains adjacent to the unsplit token.                                                                                                                                             |
| `<` generic application                | speculation, lookup, and sometimes semantic checking disambiguate it                                                      | **Preserve**, replace ad hoc speculation with staged, lookup-directed classification          | **Closed**: if any visible head candidate has a generic binder, parse `<...>` as generic application even when non-generic overloads coexist. Blocked lookup blocks parsing rather than selecting the relational interpretation.                                                                  |
| cast vs parenthesized expr             | may depend on declaration lookup and whitespace flags                                                                     | **Preserve** for the cast/declaration spellings retained by Slang 2026                        | **Closed**: the staged ambiguity query consumes lookup facts. `(T)e` has only ordinary cast semantics; in particular `(Struct)0` has no aggregate-zero-initialization escape hatch.                                                                                                               |
| declaration vs expression stmt         | parsed speculatively and may be reparsed                                                                                  | **Replace** with an explicit name-directed ambiguity resolved by the fine parse/check query   | **Closed** for the Slang 2026 surface grammar; the query retains alternatives without mutable reparsing and has no HLSL/GLSL dialect fallback.                                                                                                                                                    |
| deferred function bodies               | tokens stored in mutable `UnparsedStmt`, then moved and reparsed during checking                                          | **Replace** with exact immutable `UnparsedContent` and demand-driven parse/check queries      | Closed: terminals are referenced, never moved or copied; a complete parsed file is only a derived tooling/serialization view.                                                                                                                                                                     |
| parser recovery                        | tokens can be skipped without CST representation; repeated recovery force-advances                                        | **Replace** with missing terminals, skipped-token non-terminals, and production recovery sets | Preserve diagnostic wording separately; recovery CST shape becomes normative for tools.                                                                                                                                                                                                           |
| grammar annotations                    | parser recovery/version behavior lives in hand-written control flow rather than one complete grammar annotation inventory | **Open**; blocks parser generation                                                            | Add and validate `@recover` and `@language-version` on every affected `grammar.ebnf` production before freezing or generating the replacement parser. HLSL/GLSL dialect gates are not members of this grammar.                                                                                    |
| dialects                               | HLSL/GLSL/Slang modes influence grammar and declarations                                                                  | **IntentionalChange**: this first edition specifies Slang 2026 only                           | **Closed for scope**: HLSL/GLSL input-dialect productions and semantic fallbacks are outside the normative grammar. A shared implementation path is not evidence that a construct belongs to Slang.                                                                                               |
| GLSL compatibility modifiers           | the shared parser accepts `highp`, `lowp`, `mediump`, `layout(...)`, and `hitAttributeEXT`                                | **IntentionalChange**: exclude legacy-GLSL surface syntax                                     | **Closed**: these spellings are absent from the Slang 2026 grammar. Equivalent Slang attributes or standard-environment declarations, when specified, are distinct language constructs.                                                                                                           |
| HLSL-derived binding suffixes          | `register(...)` is widespread in `.slang` sources; `packoffset(...)` is documented and tested primarily as HLSL syntax    | **Open**                                                                                      | Language-owner decision required: retain either spelling as first-class Slang 2026 binding syntax, or exclude it with the legacy HLSL dialect. Both are absent from the normative grammar until that decision closes; their presence in the current shared parser is not by itself a disposition. |
| property/subscript reference accessors | current parsing recognizes `ref` contextually and does not provide one authoritative access-indexed surface-role table    | **IntentionalChange** with soft accessor spellings `constref` and `ref`                       | Closed by `PAR-ACC-001/002`: unbracketed `constref` maps to `AccessorRole.RefAccessor(ReadAccess)`, unbracketed `ref` maps to `AccessorRole.RefAccessor(ReadWriteAccess)`, and both are distinct from `__constref` parameter mode and `[constref]` receiver syntax.                               |
| comma expression                       | accepted by older modes and shares punctuation with tuple/list separators                                                 | **IntentionalChange**: no comma operator in Slang 2026                                        | **Closed**: comma is owned only by named separated-sequence productions. `a, b;` is invalid; `(a, b)` is tuple syntax.                                                                                                                                                                            |
| class generic clause                   | the current parser omits the inline generic clause accepted on other nominal declarations                                 | **IntentionalChange**: make classes symmetric with structs and interfaces                     | **Closed**: classes may own a `GenericBinder` through inline generic syntax or the retained `__generic` wrapper spelling.                                                                                                                                                                         |
| explicit `__generic` wrapper           | represented by an outer `GenericDecl` parent                                                                              | **Preserve syntax, replace semantics**                                                        | **Closed**: the CST retains the wrapper terminals, but scope wiring and checking attach one binder to the enclosed declaration; no semantic wrapper declaration survives.                                                                                                                         |

| leading-zero octal integer literals    | lexer/checker accept C-style octal and frontend tests rely on it                                                          | **Open**                                                                                      | Language-owner decision required: retain it as Slang 2026 syntax or reject it as a legacy C/HLSL spelling.                                                                                                                                                                                        |
| omitted attribute separators           | attribute parsing accepts adjacent attribute items without a comma                                                        | **IntentionalChange**: require explicit commas                                                | **Closed**: `[A, B]` is valid; `[A B]` is invalid/recovered syntax. ## Semantic decisions

| Topic                         | Verified current behavior                                                                                                                                                                  | Proposed disposition                                                                                                                   | Resolution or remaining work                                                                                                                                                                                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| type expressions              | `Expr` may denote type; `TypeType`/`TypeExp` encode classification imperfectly                                                                                                             | **Replace** with explicit `Classifier` and internal `Kind`                                                                             | **Closed for this edition**: kinds are checker-internal and have no source reflection/reification API.                                                                                                                                                                                                                                       |
| function receiver             | implicit `this` is absent from `FuncType` and recovered from nesting/context                                                                                                               | **Replace** with a structural receiver in `FuncType`                                                                                   | **Closed**: every non-static member has exactly one explicit receiver slot carrying self type, passing mode, and qualifiers; static/free callables use none. Interface `This`, constructors, accessors, and extensions use their named rules, and `[constref]` is never the unbracketed `constref` accessor role.                            |
| parameter direction           | encoded in pointer-like wrapper types and sometimes reread from `ParamDecl`                                                                                                                | **Replace** with structural `ParamPassingMode` and orthogonal physical/abstract operand domains                                        | **Closed**: the source modes are exactly `in`, `out`, `inout`, `__constref`, and `__ref`. `in out` and `borrow` are not aliases; `readonly`/`writeonly` remain separate access-qualifier spellings and cannot synthesize a parameter mode.                                                                                                   |
| callable parameter labels     | parameter names and named-argument lookup exist, but their exact participation in redeclaration, overload identity, function conversion, and mangling has not been inventoried as one rule | **Preserve for argument mapping; exclude from identity**                                                                               | **Closed**: labels select parameter slots only. Callable identity uses the function name, result type, receiver/modes, and parameter types/modes; source parameter names, labels, and generic-parameter names never distinguish identities.                                                                                                  |
| `This` in interface           | dedicated `ThisTypeDecl`; concrete self is supplied through witness/substitution                                                                                                           | **Preserve**, represent as bound `ThisType`; reject interface-target extensions                                                        | **Closed**: `extension IFoo` is ill-formed in this edition; neither the existential box nor all conforming `This` values receive such an extension.                                                                                                                                                                                          |
| error recovery                | `ErrorExpr`/`ErrorType`; some conversions accept errors to suppress cascades                                                                                                               | **Preserve**, replace with typed `ErrorId` recovery                                                                                    | Define root-error propagation and diagnostic suppression per judgment.                                                                                                                                                                                                                                                                       |
| value category                | `QualType` has type plus one l-value bit                                                                                                                                                   | **Replace** with disjoint physical/abstract storage, explicit access, and physical-location proofs                                     | **Closed**: `in` is abstract immutable; `out`/`inout` are exact-type abstract mutable modes with no conversion/rvalue materialization and normal-return-only write-back; `__constref`/`__ref` require exact immutable/mutable physical endpoints and never materialize. Properties require the exact `constref`/`ref` accessor.              |
| decl-ref                      | canonical declaration plus linked substitution shapes and lookup witnesses                                                                                                                 | **Preserve** only for fully applied canonical references; add a distinct pending generic-use candidate                                 | **Closed**: lookup may carry an unapplied declaration plus pending direct binder while inference runs. A `DeclRef` is created only after every frame is complete; partial generic values carry an explicit residual binder rather than an incomplete `DeclRef`.                                                                              |
| facets                        | mutable linearized list of self/base/extension member providers                                                                                                                            | **Replace** with target-keyed canonical witnesses/facets and a proof-carrying specificity relation                                     | **Closed at the semantic level**: each `(subType, superType)` target has one selected witness/path. Exact/non-generic and strictly more-specific extension targets dominate as specified in chapter 15; incomparable or tied providers are diagnosed, never source/import ordered.                                                           |
| concrete struct inheritance   | accepted with legacy warnings in older language modes and rejected by modern Slang                                                                                                         | **IntentionalChange**: excluded from the replacement semantic language                                                                 | **Closed**: recovery may diagnose old source, but creates no checked base, facet, subobject, initialization slot, or IR conversion.                                                                                                                                                                                                          |
| visibility                    | `Private < Internal < Public`; effective visibility uses minimum; defaults depend on language version                                                                                      | **Preserve** the lattice; make the Slang 2026 defaults explicit                                                                        | **Closed**: a namespace scope identity is `Public`; accessors, enum cases, interface requirements, generic parameters, and constraints inherit their owner; every other source declaration uses its module default or implicit `Internal`, followed by the owner cap. Synthesis uses an explicit `SynthesisVisibilityPlan`.                  |
| overload diagnostics          | candidates are retained through staged applicability failures for better diagnostics                                                                                                       | **Preserve**                                                                                                                           | **Closed**: semantic candidate selection and “best failed candidate” diagnostic ranking are separate relations; changing the latter cannot change a successful winner.                                                                                                                                                                       |
| conversion costs              | base costs plus special rules and declared conversions                                                                                                                                     | **Preserve as ordered semantic categories, not an ABI**                                                                                | **Closed**: a candidate's primary conversion rank is the single maximum across receiver and all supplied-argument adaptations, never a sum. The per-source vector is retained only for proof and diagnostics, not pointwise semantic dominance. An implicit conversion contains at most one user-defined step.                               |
| generic solving               | unification/constraint solving covers types, values, packs, conformance, coercion, and differential info                                                                                   | **Preserve**, replace with typed constraints/evidence and explicit residual binders                                                    | **Closed at the language-policy level**: occurs checks/conflicts are structured failures; defaults apply only after deduction; unresolved-but-valid binders may produce first-class partially applied function or type generics.                                                                                                             |
| scheduler cycle policies      | ad hoc declaration states and recursion guards give different queries implicit cycle behavior                                                                                              | **Replace** with centralized keyed queries and an explicit policy per query kind                                                       | **Deferred by the language owner**: chapter 11's table is the concrete proposal and test target, not a frozen decision. Implementation must not choose a different implicit policy; final per-query review remains open.                                                                                                                     |
| conformance witnesses         | requirement dictionary keyed by requirement declaration; values are decl-ref/Val/nested table                                                                                              | **Replace** with one canonical target witness, generic/specialized witness-table values, and kind-indexed immutable requirement lookup | **Closed**: duplicate providers for one target must have one unique specificity winner or are diagnosed. Type-valued requirement lookup is a `Type`; callable and constant/value lookups inhabit their corresponding semantic domains.                                                                                                       |
| omitted initialization        | behavior varies by declaration site, language version, and zero-initialization options                                                                                                     | **IntentionalChange**: omission never calls `__init()`                                                                                 | **Closed**: a mutable local `Foo foo;` leaves storage uninitialized even when `Foo.__init()` exists. Other declaration sites follow their explicit site policy; storage classes that require an independently specified zero-initialized image remain separate from source-level construction and cannot be justified by a constructor call. |
| explicit type initialization  | `T(e)` and `(T)e` share conversion/initializer behavior through implementation fallbacks                                                                                                   | **Replace** with named cast, constructor, and C-style aggregate strategies                                                             | **Closed**: `= {args}` invokes `__init(args)` for a non-C-style type. `(T)e` is an ordinary retained cast and `(Struct)0` receives no legacy aggregate-zero meaning.                                                                                                                                                                         |
| aggregate initialization      | partial/flattened/default behavior varies across modes and implementation paths                                                                                                            | **IntentionalChange** with a closed C-style/non-C-style split                                                                          | **Closed**: a type with user-defined constructors is non-C-style; its list is nested and missing fields are errors. A C-style type has no user constructors, may use flattened lists, and zero-fills missing fields.                                                                                                                         |
| differential type evidence    | mutable dictionaries and special witness classes bridge frontend and IR autodiff                                                                                                           | **Replace** with `ValueDifferentialInfo` and ordinary keyed interface-subtype witnesses                                                | **Closed**: pointer/reference-shaped types request pointer-differential evidence; other values request value-differential evidence. A registered dual interpretation must select the exact role or is ambiguous. Missing evidence for an active promised slot rejects checking.                                                              |
| callable differentiation      | signature roles are reconstructed from modifiers/wrapper types in multiple layers                                                                                                          | **Replace** with explicit participation and `DerivativeSignatureMap`                                                                   | **Closed**: backward implies forward; `Through(n)` covers orders `1...n` and omission means `Through(1)`. Throwing callables and physical `ConstRefMode`/`RefMode` roles are rejected unless an exact registered rule supplies the complete mapping; a physical mode never falls back to `InMode` or a temporary.                            |
| derivative provider selection | attributes, witness methods, builtins, and synthesis have implementation-defined staging                                                                                                   | **Replace** with immutable provider candidates and a named partial priority                                                            | **Closed**: an exact dispatch-mandated or explicitly associated provider precedes synthesis; synthesis precedes an exact declaration-local `[TreatAsDifferentiable]` assumed-zero trust fallback. Same-tier incomparable providers remain ambiguous, never source ordered.                                                                   |
| `no_diff`                     | represented through downstream differentiation handling                                                                                                                                    | **Preserve**, replace with typed participation and detach-derivative boundaries                                                        | **Closed**: declaration use is limited to receiver/parameter/result/stored-field participation; expression use requires a differentiability context and a value, cannot detach storage identity, and preserves ordinary effects, capabilities, access, exceptions, initialization, and alias contracts.                                      |
| capability set                | disjunction of conjunctions with implication/incompatibility graph                                                                                                                         | **Preserve** with logic-bearing operations                                                                                             | **Closed**: `TrueFormula` means no requirement and `FalseFormula` means impossible. Requirement accumulation is strict conjunction via `requireAll`; intentional alternatives use `allowEither`; availability and compatibility are logical implication, with no extra abstract target/stage equality test.                                  |
| capability inference          | function/body dependencies accumulate; recursion is handled by declaration staging rather than an explicit solver                                                                          | **Preserve**, use least fixpoint                                                                                                       | **Closed**: the versioned finite capability universe and canonical positive-DNF antichain define a finite requirement lattice. SCC inference starts at `TrueFormula` and monotonically joins with `requireAll` to the least fixpoint; no heuristic widening changes the contract.                                                            |
| constant evaluation           | several `Val` subclasses plus checker/IR folding paths                                                                                                                                     | **Open**                                                                                                                               | Inventory the authoritative evaluator and move all type-required constants behind one query.                                                                                                                                                                                                                                                 |

## Required evidence before implementation freeze

For every row in the feature matrix:

1. enumerate parser entry functions and syntax registration entries;
2. enumerate all AST node kinds and standard-environment declarations involved;
3. enumerate semantic entry functions and diagnostics;
4. enumerate IRReady/IR mappings and any “must not reach lowering” assertions;
5. map existing positive/negative tests;
6. assign a disposition and normative rule IDs; and
7. generate missing validation cases.

The implementation may begin experimentally before every row is closed, but a replacement cannot
claim language compatibility while an `O` row lacks an explicit fallback to the old frontend.

## Known documentation/source discrepancies

These items require explicit resolution and should not be copied from generated documentation:

- lexer backslash-newline scrubbing means logical spelling is not always the token's contiguous
  physical spelling;
- ordinary macro-expanded tokens do not retain a full expansion-origin chain;
- unterminated block-comment behavior in source does not currently match the language-reference
  diagnostic claim directly; and
- several generated design documents declare that they may drift from source.

The flat lossless token model and per-token origin DAG deliberately fix the first two representation
gaps. User-visible lexical diagnostics still need compatibility decisions in chapter 2.
